# 포워딩 모드 (Forward)

## 이 옵션이 하는 일

BIND가 자신이 모르는 도메인에 대한 쿼리를 받았을 때, 다른 DNS 서버(포워더)로 전달하는 방식을 지정합니다.

## 선택지 설명

### first (먼저 포워더 시도)
- **의미**: 먼저 포워더에게 질의하고, 실패하면 루트 DNS 서버에 질의
- **효과**: 빠른 응답 (포워더가 캐시를 가지고 있을 가능성)
- **사용 시기**: **대부분의 경우 권장**

### only (포워더만 사용)
- **의미**: 오직 포워더에게만 질의, 루트 DNS 서버는 사용 안 함
- **효과**: 포워더에 의존, 포워더가 다운되면 DNS 쿼리 실패
- **사용 시기**: 내부 네트워크, 특정 DNS 서버만 사용해야 하는 경우

## 동작 방식

### first 모드
1. 클라이언트가 `example.com` 질의
2. BIND가 포워더(예: 8.8.8.8)에게 먼저 질의
3. 포워더가 응답 없으면 루트 DNS 서버에 질의
4. 결과 반환

### only 모드
1. 클라이언트가 `example.com` 질의
2. BIND가 포워더에게만 질의
3. 포워더가 응답 없으면 실패
4. 루트 DNS 서버는 사용 안 함

## 알아야 할 것들

### 포워더란?

다른 DNS 서버를 의미합니다:
- **공용 DNS**: Google (8.8.8.8), Cloudflare (1.1.1.1)
- **ISP DNS**: 인터넷 제공업체의 DNS 서버
- **내부 DNS**: 회사 내부의 다른 DNS 서버

### first 모드의 장점

- **빠른 응답**: 포워더의 캐시 활용
- **안정성**: 포워더 실패 시 루트 DNS로 폴백
- **유연성**: 여러 경로로 질의 가능

### only 모드의 사용 사례

- **내부 네트워크**: 외부 DNS 접근 차단
- **정책 준수**: 특정 DNS 서버만 사용해야 하는 경우
- **트래픽 제어**: 모든 쿼리를 특정 서버로만 전달

## 자주 발생하는 오류

### DNS 쿼리가 느림
**원인**: 포워더가 느리거나 응답이 없어서 루트 DNS로 폴백

**해결 방법**:
1. 빠른 포워더 사용 (예: 1.1.1.1, 8.8.8.8)
2. 여러 포워더 지정 (로드 밸런싱)
3. `first` 모드 사용 (권장)

### 포워더가 다운되면 DNS가 안 됨 (only 모드)
**원인**: `only` 모드에서 포워더에만 의존

**해결 방법**:
1. 여러 포워더 지정
2. 또는 `first` 모드로 변경

### 내부 도메인이 안 됨
**확인 사항**:
1. 내부 도메인은 Zone 파일에 정의되어 있어야 함
2. 포워더는 외부 도메인만 처리
3. Zone 설정 확인
