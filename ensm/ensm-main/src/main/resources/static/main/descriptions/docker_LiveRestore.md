# 라이브 복원 (Live Restore)

## 이 옵션이 하는 일

Docker 데몬이 재시작되어도 실행 중인 컨테이너가 계속 실행되도록 할지 결정합니다. 일반적으로 Docker 데몬 재시작 시 모든 컨테이너가 중지됩니다.

## 동작 방식

### 활성화 시 (ON, 권장)
- Docker 데몬 재시작 시 컨테이너 계속 실행
- 서비스 중단 없음
- 고가용성 향상

### 비활성화 시 (OFF)
- Docker 데몬 재시작 시 모든 컨테이너 중지
- 서비스 중단 발생
- 재시작 후 컨테이너 수동 시작 필요

## 사용 시나리오

### 활성화가 권장되는 경우 (대부분)
- **프로덕션 환경**: 서비스 중단 방지
- **중요한 서비스**: 24/7 운영 필요
- **고가용성**: 최대 가동 시간

### 비활성화가 가능한 경우
- **개발 환경**: 재시작 시 깨끗한 상태 필요
- **테스트**: 재시작 동작 테스트

## 알아야 할 것들

### Docker 데몬 재시작

Docker 데몬 재시작이 필요한 경우:
- Docker 업데이트
- 설정 변경
- 시스템 재부팅 (live-restore는 재부팅에는 적용 안 됨)

### 제한사항

live-restore는 다음에는 적용되지 않습니다:
- 시스템 재부팅
- Docker 완전 종료
- 컨테이너 자체 오류

### 컨테이너 관리

live-restore 활성화 시:
- `docker stop` 명령어로 수동 중지 가능
- 컨테이너는 정상적으로 관리 가능
- 데몬 재시작만 영향 없음

## 자주 발생하는 오류

### 데몬 재시작 후 컨테이너가 중지됨
**원인**: `live_restore`가 비활성화됨

**해결 방법**:
1. `live_restore` 활성화
2. Docker 재시작
3. 컨테이너는 계속 실행됨

### 컨테이너가 응답하지 않음
**확인 사항**:
1. 컨테이너 상태 확인: `docker ps`
2. 로그 확인: `docker logs <container>`
3. 네트워크 연결 확인
