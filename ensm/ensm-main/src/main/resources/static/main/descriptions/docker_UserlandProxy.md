# 사용자 공간 프록시 (Userland Proxy)

## 이 옵션이 하는 일

Docker가 포트 포워딩에 사용자 공간 프록시를 사용할지 결정합니다. 활성화하면 컨테이너 포트를 호스트 포트로 매핑할 때 프록시를 사용합니다.

## 동작 방식

### 활성화 시 (ON, 기본값)
- 사용자 공간 프록시 사용
- 포트 포워딩 처리
- 안정적이고 호환성 좋음

### 비활성화 시 (OFF)
- iptables 규칙 직접 사용
- 프록시 없이 직접 포워딩
- 성능 향상 가능하지만 호환성 문제 가능

## 사용 시나리오

### 활성화가 권장되는 경우 (대부분)
- **일반적인 사용**: 대부분의 경우
- **안정성**: 호환성과 안정성 중요
- **문제 해결**: 포트 포워딩 문제 시

### 비활성화가 가능한 경우
- **성능 최적화**: 성능이 중요한 경우
- **특수한 네트워크**: 특정 네트워크 구성

## 알아야 할 것들

### 포트 포워딩

컨테이너 포트를 호스트 포트로 매핑:
- 예: `docker run -p 8080:80 nginx`
- 호스트 8080 → 컨테이너 80

### 성능 차이

**활성화 시**:
- 프록시를 통한 전달
- 약간의 오버헤드
- 안정적

**비활성화 시**:
- 직접 iptables 규칙
- 성능 향상 가능
- 일부 환경에서 문제 가능

### 호환성

대부분의 환경에서 활성화가 안전합니다:
- Linux 커널 기능 사용
- 널리 테스트됨
- 문제 발생 시 비활성화 고려

## 자주 발생하는 오류

### 포트 포워딩이 작동하지 않음
**원인**: 
- `userland_proxy` 비활성화로 인한 호환성 문제
- 네트워크 설정 문제

**해결 방법**:
1. `userland_proxy` 활성화
2. 네트워크 설정 확인
3. iptables 규칙 확인

### 성능 문제
**원인**: 프록시 오버헤드

**해결 방법**:
1. `userland_proxy` 비활성화 시도
2. 네트워크 성능 확인
3. 다른 최적화 방법 고려
