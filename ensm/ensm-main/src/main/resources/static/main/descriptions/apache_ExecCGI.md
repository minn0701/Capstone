# CGI 실행 허용 (ExecCGI)

## 이 옵션이 하는 일

웹 디렉토리에서 CGI(Common Gateway Interface) 스크립트를 실행할 수 있게 할지 결정합니다. CGI는 웹 서버가 외부 프로그램을 실행하여 동적 콘텐츠를 생성하는 방식입니다.

## 동작 방식

### 활성화 시 (ON)
- CGI 스크립트(예: `.cgi`, `.pl`, `.py`) 실행 가능
- 스크립트가 실행되어 결과를 웹 페이지로 반환
- **보안 위험**: 잘못된 스크립트가 시스템에 손상 줄 수 있음

### 비활성화 시 (OFF, 권장)
- CGI 스크립트 실행 불가
- 스크립트 파일은 일반 파일로만 처리
- **보안**: 스크립트 실행으로 인한 위험 방지

## 사용 시나리오

### 활성화가 필요한 경우
- **레거시 애플리케이션**: 오래된 CGI 스크립트 사용
- **특정 디렉토리**: 특정 폴더에서만 CGI 실행 필요
- **개발 환경**: CGI 스크립트 테스트

### 비활성화가 권장되는 경우 (대부분)
- **현대적 웹 애플리케이션**: PHP, Python WSGI 등 사용
- **보안**: 불필요한 실행 권한 제거
- **프로덕션 환경**: 최소 권한 원칙

## 알아야 할 것들

### CGI란?

CGI는 웹 서버가 외부 프로그램을 실행하는 오래된 방식입니다:
- **장점**: 간단한 스크립트 실행 가능
- **단점**: 각 요청마다 프로세스 생성으로 성능 저하
- **대안**: PHP, Python WSGI, Node.js 등

### CGI 스크립트 예시

```perl
#!/usr/bin/perl
print "Content-Type: text/html\n\n";
print "<h1>Hello, CGI!</h1>";
```

```python
#!/usr/bin/python3
print("Content-Type: text/html\n")
print("<h1>Hello, CGI!</h1>")
```

### 특정 디렉토리만 활성화

모든 디렉토리가 아닌 특정 디렉토리에만 활성화하는 것이 안전합니다:

```apache
<Directory /var/www/html>
    Options -ExecCGI  # 기본적으로 비활성화
</Directory>

<Directory /var/www/html/cgi-bin>
    Options +ExecCGI  # cgi-bin 폴더만 활성화
</Directory>
```

### 보안 고려사항

**위험한 예시**:
- 사용자가 업로드한 스크립트 실행
- 잘못된 권한 설정으로 시스템 명령 실행
- 스크립트 취약점 악용

**안전한 설정**:
- 필요한 디렉토리에만 활성화
- 스크립트 업로드 제한
- 적절한 파일 권한 설정

## 자주 발생하는 오류

### "403 Forbidden" 또는 "500 Internal Server Error"
**원인**: 
- `ExecCGI`가 비활성화됨
- 스크립트 실행 권한이 없음
- 스크립트 문법 오류

**해결 방법**:
1. 필요한 디렉토리에만 `ExecCGI` 활성화
2. 스크립트 실행 권한 부여: `chmod +x script.cgi`
3. 스크립트 문법 확인

### 스크립트가 실행되지 않음
**확인 사항**:
1. `ExecCGI` 옵션 활성화 확인
2. 스크립트 파일 권한 확인
3. 스크립트 첫 줄에 shebang 확인 (`#!/usr/bin/perl`)
4. 스크립트 경로 확인

### 보안 스캔에서 경고
**원인**: `ExecCGI` 활성화로 인한 보안 위험

**해결 방법**:
1. 불필요한 경우 비활성화
2. 특정 디렉토리에만 제한
3. 스크립트 업로드 제한
4. 정기적인 보안 점검

### 성능 저하
**원인**: CGI는 각 요청마다 프로세스를 생성하여 느림

**해결 방법**:
- PHP, Python WSGI 등 현대적 방법 사용 권장
- CGI는 레거시 애플리케이션에만 사용
