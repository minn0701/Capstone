# 심볼릭 링크 추적 (FollowSymLinks)

## 이 옵션이 하는 일

웹 디렉토리 안의 심볼릭 링크(바로가기)를 따라가서 실제 파일에 접근할 수 있게 할지 결정합니다. 심볼릭 링크는 다른 위치의 파일이나 디렉토리를 가리키는 특수한 파일입니다.

## 동작 방식

### 활성화 시 (ON)
- 심볼릭 링크를 따라가서 실제 파일에 접근 가능
- 링크가 가리키는 파일을 웹에서 제공
- **보안 위험**: 링크가 시스템의 다른 부분을 가리킬 수 있음

### 비활성화 시 (OFF)
- 심볼릭 링크를 무시
- 링크 자체는 접근 불가
- **보안**: 웹 루트 밖의 파일 접근 방지

## 사용 시나리오

### 활성화가 유용한 경우
- **파일 공유**: 여러 디렉토리의 파일을 한 곳에서 접근
- **버전 관리**: 현재 버전을 가리키는 링크 사용
- **개발 환경**: 유연한 파일 구조 관리

### 비활성화가 권장되는 경우
- **프로덕션 환경**: 보안상 안전
- **공개 웹사이트**: 의도치 않은 파일 노출 방지
- **호스팅 환경**: 사용자가 시스템 파일에 접근하는 것 방지

## 알아야 할 것들

### 보안 고려사항

**위험한 예시**:
```bash
# 웹 루트에 심볼릭 링크 생성
ln -s /etc/passwd /var/www/html/passwd
```
→ `FollowSymLinks`가 활성화되어 있으면 `/etc/passwd` 파일이 웹에서 접근 가능!

**안전한 대안**: `SymLinksIfOwnerMatch` 사용
- 소유자가 같은 경우에만 링크를 따라감
- 보안과 유연성의 균형

### 심볼릭 링크 예시

```bash
# 현재 버전을 가리키는 링크
ln -s /var/www/versions/v2.0 /var/www/html/current

# 공유 파일 디렉토리 링크
ln -s /shared/files /var/www/html/files
```

### SymLinksIfOwnerMatch와의 차이

- **FollowSymLinks**: 모든 심볼릭 링크를 무조건 따라감
- **SymLinksIfOwnerMatch**: 소유자가 같은 경우에만 따라감 (더 안전)

## 자주 발생하는 오류

### "403 Forbidden" 오류 (심볼릭 링크)
**원인**: `FollowSymLinks`가 비활성화되어 있음

**해결 방법**:
1. 필요한 경우 활성화 (보안 고려)
2. 또는 `SymLinksIfOwnerMatch` 사용 (권장)

### 보안 스캔에서 경고
**원인**: `FollowSymLinks` 활성화로 인한 보안 위험

**해결 방법**:
1. 비활성화 (가장 안전)
2. 또는 `SymLinksIfOwnerMatch`로 변경
3. 심볼릭 링크 사용 최소화

### 링크가 작동하지 않음
**확인 사항**:
1. `FollowSymLinks` 또는 `SymLinksIfOwnerMatch` 활성화 확인
2. 링크가 올바르게 생성되었는지 확인 (`ls -l`)
3. 링크가 가리키는 파일/디렉토리가 존재하는지 확인
4. 파일 권한 확인

### 의도치 않은 파일 노출
**원인**: 심볼릭 링크가 시스템 파일을 가리킴

**해결 방법**:
1. 즉시 `FollowSymLinks` 비활성화
2. 문제가 되는 심볼릭 링크 제거
3. `SymLinksIfOwnerMatch` 사용 고려
