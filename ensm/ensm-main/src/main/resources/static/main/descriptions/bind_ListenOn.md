# IPv4 수신 주소 (ListenOn)

## 이 옵션이 하는 일

BIND DNS 서버가 어떤 IPv4 주소(네트워크 인터페이스)에서 DNS 쿼리를 받을지 지정합니다. 특정 IP 주소에서만 수신하거나 모든 인터페이스에서 수신할 수 있습니다.

## 기본값

- **기본값**: `127.0.0.1` (localhost만)
- **모든 인터페이스**: `any` 또는 비워두기

## 설정 예시

### localhost만 (기본값)
```
127.0.0.1
```
→ 로컬 컴퓨터에서만 DNS 쿼리 받음

### 모든 IPv4 인터페이스
```
any
```
→ 모든 네트워크 인터페이스에서 수신 (공용 DNS 서버)

### 특정 IP 주소
```
192.168.1.100
10.0.0.50
```
→ 지정한 IP 주소에서만 수신

### 여러 IP 주소
```
192.168.1.100; 10.0.0.50;
```
→ 여러 IP 주소에서 수신 (세미콜론으로 구분)

## 알아야 할 것들

### 보안 고려사항

**localhost만 (127.0.0.1)**:
- ✅ 가장 안전
- ❌ 다른 컴퓨터에서 접근 불가
- 사용 시기: 로컬 개발, 캐싱 전용 DNS

**모든 인터페이스 (any)**:
- ✅ 외부 접근 가능
- ⚠️ 보안 위험 (공격 가능)
- 사용 시기: 공용 DNS 서버

**특정 IP**:
- ✅ 안전하면서도 유연
- 권장: 내부 네트워크 IP만 지정

### 네트워크 인터페이스 확인

서버의 IP 주소 확인:

```bash
# 모든 네트워크 인터페이스 확인
ip addr show

# 또는
ifconfig

# 특정 인터페이스만
ip addr show eth0
```

### 내부 vs 외부 DNS

- **내부 DNS**: 내부 네트워크 IP만 지정 (예: `192.168.1.100`)
- **공용 DNS**: `any` 또는 공용 IP 주소 지정

## 자주 발생하는 오류

### 다른 컴퓨터에서 DNS 쿼리가 안 됨
**원인**: `127.0.0.1`로 설정되어 localhost만 수신

**해결 방법**:
1. `any`로 변경 (모든 인터페이스)
2. 또는 내부 네트워크 IP 주소 지정

### 보안 스캔에서 경고
**원인**: `any`로 설정되어 외부 접근 가능

**해결 방법**:
1. 필요한 IP 주소만 지정
2. 내부 네트워크 IP만 사용
3. 방화벽으로 추가 보호

### 여러 네트워크 인터페이스
**해결 방법**:
- 필요한 인터페이스의 IP 주소만 지정
- 또는 `any` 사용 후 방화벽으로 제어
