# NFS 공유 설정 (Exports)

## 이 옵션이 하는 일

어떤 디렉토리를 네트워크에 공유할지, 누가 접근할 수 있는지, 어떤 권한을 가질지 지정합니다. `/etc/exports` 파일의 내용을 설정합니다.

## 기본 형식

```
/공유할/경로 클라이언트(옵션1,옵션2,옵션3)
```

## 설정 예시

### 모든 클라이언트에 읽기/쓰기 허용
```
/var/nfs * (rw,sync,no_subtree_check)
```
→ 모든 IP에서 읽기/쓰기 가능

### 특정 네트워크만 허용
```
/var/nfs 192.168.1.0/24 (rw,sync,no_subtree_check)
```
→ 192.168.1.x 네트워크만 접근 가능

### 읽기 전용 공유
```
/var/nfs 192.168.1.0/24 (ro,sync)
```
→ 읽기만 가능, 쓰기 불가

### 여러 클라이언트 조합
```
/var/nfs 192.168.1.10(rw,sync) 192.168.1.20(ro,sync)
```
→ 각 클라이언트마다 다른 권한

### 루트 사용자 매핑
```
/var/nfs * (rw,sync,no_root_squash)
```
→ 클라이언트의 root를 서버의 root로 매핑 (위험)

## 주요 옵션 설명

### rw (read-write)
- **의미**: 읽기/쓰기 허용
- **사용 시기**: 파일 수정이 필요한 경우

### ro (read-only)
- **의미**: 읽기 전용
- **사용 시기**: 배포용 파일, 백업 등

### sync
- **의미**: 동기식 쓰기 (데이터 안전성)
- **효과**: 쓰기 완료 후 응답 (느릴 수 있음)
- **권장**: 대부분의 경우

### async
- **의미**: 비동기식 쓰기 (성능)
- **효과**: 즉시 응답 (데이터 손실 위험)
- **주의**: 사용 시 주의 필요

### no_subtree_check
- **의미**: 서브트리 검사 비활성화
- **효과**: 성능 향상
- **권장**: 대부분의 경우

### root_squash
- **의미**: 클라이언트의 root를 nobody로 매핑 (보안)
- **권장**: 보안상 권장

### no_root_squash
- **의미**: 클라이언트의 root를 서버의 root로 매핑
- **위험**: 보안 위험
- **주의**: 신뢰할 수 있는 네트워크에서만 사용

## 알아야 할 것들

### 디렉토리 권한

공유할 디렉토리에 적절한 권한이 필요합니다:

```bash
# 디렉토리 생성 및 권한 설정
sudo mkdir -p /var/nfs
sudo chmod 755 /var/nfs
sudo chown nobody:nogroup /var/nfs
```

### exports 적용

설정 변경 후 exports를 다시 내보내야 합니다:

```bash
# exports 재적용
sudo exportfs -ra

# 또는 NFS 서비스 재시작
sudo systemctl restart nfs-server
```

### 보안 고려사항

**권장 설정**:
- 내부 네트워크만 허용
- `root_squash` 사용 (기본값)
- 필요한 최소 권한만 부여

**위험한 설정**:
- `*` (모든 클라이언트) + `rw` + `no_root_squash`
- 외부 네트워크 접근 허용

## 자주 발생하는 오류

### "Permission denied" 오류
**원인**: 
- 디렉토리 권한 문제
- exports 설정 오류
- 클라이언트 IP가 허용 목록에 없음

**해결 방법**:
1. 디렉토리 권한 확인
2. exports 설정 확인
3. 클라이언트 IP 확인

### 마운트는 되는데 쓰기가 안 됨
**원인**: `ro` (read-only) 옵션 사용

**해결 방법**:
- `rw` 옵션으로 변경
- exports 재적용

### "Stale file handle" 오류
**원인**: 
- 서버에서 디렉토리가 삭제됨
- exports 설정이 변경됨

**해결 방법**:
1. 디렉토리 존재 확인
2. 마운트 해제 후 다시 마운트
3. exports 설정 확인
