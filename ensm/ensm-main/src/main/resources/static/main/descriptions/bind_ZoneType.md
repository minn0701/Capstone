# Zone 타입 (Zone Type)

## 이 옵션이 하는 일

DNS Zone의 역할을 지정합니다. Zone은 주 서버(master), 보조 서버(slave), 또는 힌트(hint) 역할을 할 수 있습니다.

## 선택지 설명

### master (주 서버)
- **의미**: 이 서버가 Zone의 원본 데이터를 가지고 있음
- **역할**: Zone 파일을 직접 관리하고 수정
- **사용 시기**: **대부분의 경우** (단일 서버 또는 주 서버)

### slave (보조 서버)
- **의미**: 주 서버로부터 Zone 데이터를 복제받음
- **역할**: 주 서버의 백업, 로드 분산
- **사용 시기**: 여러 DNS 서버를 운영할 때

### hint (루트 힌트)
- **의미**: 루트 DNS 서버 목록 제공
- **역할**: 다른 DNS 서버가 루트 서버를 찾을 수 있도록 도움
- **사용 시기**: 특수한 경우 (일반적으로 사용 안 함)

## 동작 방식

### master (주 서버)
1. Zone 파일을 직접 읽고 관리
2. DNS 쿼리에 응답
3. slave 서버에 Zone 데이터 전송

### slave (보조 서버)
1. 주 서버로부터 Zone 데이터를 주기적으로 복제
2. 복제받은 데이터로 DNS 쿼리에 응답
3. 주 서버가 다운되어도 서비스 계속

### hint (루트 힌트)
- 루트 DNS 서버 목록만 제공
- 일반적인 Zone 관리와는 다름

## 알아야 할 것들

### master-slave 구성

여러 DNS 서버를 운영할 때:
- **master**: 원본 데이터 관리
- **slave**: 백업 및 로드 분산
- **장점**: 고가용성, 성능 향상

### Zone 파일 위치

- **master**: Zone 파일 직접 관리 (`/var/named/example.com.zone`)
- **slave**: 자동으로 복제받아 저장 (보통 `/var/named/slaves/`)

## 자주 발생하는 오류

### Zone이 동기화되지 않음 (slave)
**원인**: 
- 주 서버에 접근 불가
- 네트워크 문제
- 주 서버 설정 오류

**해결 방법**:
1. 주 서버 연결 확인
2. `AllowTransfer` 설정 확인
3. 네트워크 방화벽 확인

### Zone 파일을 수정했는데 반영 안 됨 (master)
**확인 사항**:
1. Zone 파일 문법 확인
2. Serial 번호 증가 확인
3. BIND 재시작 또는 Zone 리로드
