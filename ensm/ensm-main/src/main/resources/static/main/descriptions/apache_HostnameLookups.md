# 호스트명 조회 (HostnameLookups)

## 이 옵션이 하는 일

클라이언트의 IP 주소를 호스트명(도메인 이름)으로 변환할지 결정합니다. 활성화하면 로그에 IP 주소 대신 호스트명이 기록됩니다.

## 동작 방식

### 활성화 시 (ON)
- 클라이언트 IP 주소를 DNS를 통해 호스트명으로 변환
- 로그에 호스트명이 기록됨 (예: `client.example.com`)
- **성능 저하**: 각 요청마다 DNS 조회 필요

### 비활성화 시 (OFF, 권장)
- IP 주소 그대로 사용
- 로그에 IP 주소가 기록됨 (예: `192.168.1.100`)
- **성능 향상**: DNS 조회 불필요

## 기본값

- **기본값**: OFF (비활성화, 권장)

## 사용 시나리오

### 활성화가 유용한 경우
- **내부 네트워크**: 내부 DNS가 잘 구성된 환경
- **디버깅**: 호스트명으로 클라이언트 식별이 쉬운 경우
- **낮은 트래픽**: 성능 영향이 미미한 소규모 사이트

### 비활성화가 권장되는 경우 (대부분)
- **프로덕션 환경**: 성능 최적화 필요
- **대용량 트래픽**: DNS 조회로 인한 지연 방지
- **외부 클라이언트**: 역방향 DNS가 설정되지 않은 경우가 많음

## 알아야 할 것들

### 성능 영향

**활성화 시**:
- 각 요청마다 DNS 역방향 조회 필요
- 응답 시간 증가 가능
- DNS 서버 부하 증가
- 대용량 트래픽 사이트에서는 성능 저하가 클 수 있음

**비활성화 시**:
- DNS 조회 없음
- 빠른 응답 시간
- 최소한의 오버헤드

### 로그 차이

**활성화 시**:
```
client.example.com - - [15/Jan/2024:10:30:45] "GET / HTTP/1.1" 200
```

**비활성화 시**:
```
192.168.1.100 - - [15/Jan/2024:10:30:45] "GET / HTTP/1.1" 200
```

### 역방향 DNS

호스트명 조회는 역방향 DNS(Reverse DNS)를 사용합니다:
- IP 주소 → 호스트명 변환
- 모든 IP가 역방향 DNS를 가지고 있지는 않음
- 조회 실패 시 IP 주소가 그대로 기록됨

## 자주 발생하는 오류

### 성능이 느려짐
**원인**: `HostnameLookups` 활성화로 인한 DNS 조회 오버헤드

**해결 방법**:
1. 비활성화 (권장)
2. 로그 분석 시 별도로 호스트명 변환

### 로그에 IP만 표시됨
**원인**: 
- `HostnameLookups`가 비활성화됨
- 역방향 DNS가 설정되지 않음

**해결 방법**:
- 대부분의 경우 IP 주소로도 충분함
- 필요시 로그 분석 도구에서 일괄 변환

### DNS 조회 실패
**원인**: 역방향 DNS가 설정되지 않았거나 DNS 서버 응답 지연

**해결 방법**:
- 비활성화 권장 (대부분의 경우 IP 주소로 충분)
- 내부 네트워크에서만 활성화 고려

### 로그 분석이 어려움
**해결 방법**:
- 로그 분석 도구(AWStats, GoAccess 등) 사용
- 필요시 로그 후처리로 IP → 호스트명 변환
