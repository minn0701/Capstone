# HTTP SSL 인증서 검증 (HTTP SSL Verify)

## 이 옵션이 하는 일

HTTPS를 통해 Git 저장소에 접속할 때 SSL 인증서를 검증할지 결정합니다. 활성화하면 인증서가 유효하지 않으면 연결이 거부됩니다.

## 동작 방식

### 활성화 시 (ON, 권장)
- SSL 인증서 검증
- 유효하지 않은 인증서 거부
- 보안 강화

### 비활성화 시 (OFF)
- SSL 인증서 검증 안 함
- 모든 인증서 허용
- 보안 위험

## 사용 시나리오

### 활성화가 권장되는 경우 (대부분)
- **보안**: 중간자 공격 방지
- **프로덕션 환경**: 실제 사용 환경
- **공용 저장소**: GitHub, GitLab 등

### 비활성화가 필요한 경우
- **자체 서명 인증서**: 내부 Git 서버
- **개발 환경**: 테스트 목적
- **임시 우회**: 문제 해결 시 (일시적)

## 알아야 할 것들

### SSL 인증서 검증

인증서 검증은 다음을 확인합니다:
- 인증서 유효성
- 인증서 만료 여부
- 인증 기관(CA) 신뢰
- 호스트 이름 일치

### 자체 서명 인증서

내부 Git 서버에서 자체 서명 인증서 사용 시:
- 검증 실패 발생
- 일시적으로 비활성화 가능
- 또는 인증서를 신뢰 목록에 추가

### 보안 위험

비활성화 시:
- 중간자 공격 위험
- 데이터 가로채기 가능
- 인증서 위조 공격 가능

## 자주 발생하는 오류

### "SSL certificate problem" 오류
**원인**: 
- 자체 서명 인증서
- 만료된 인증서
- 신뢰할 수 없는 인증서

**해결 방법**:
1. 공인 인증서 사용 (권장)
2. 또는 인증서를 신뢰 목록에 추가
3. 일시적으로 비활성화 (개발 환경만)

### 내부 Git 서버 접속 실패
**원인**: 자체 서명 인증서로 인한 검증 실패

**해결 방법**:
1. 인증서를 시스템 신뢰 저장소에 추가
2. 또는 일시적으로 비활성화 (주의)
3. 공인 인증서 사용 권장

### 보안 스캔에서 경고
**원인**: `http.sslVerify`가 비활성화됨

**해결 방법**:
1. 활성화 (권장)
2. 공인 인증서 사용
3. 또는 내부 네트워크에서만 비활성화
