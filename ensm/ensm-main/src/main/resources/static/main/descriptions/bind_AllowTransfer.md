# 전송 허용 (AllowTransfer)

## 이 옵션이 하는 일

어떤 서버가 이 DNS 서버로부터 Zone 데이터를 복제(전송)받을 수 있는지 지정합니다. slave DNS 서버가 master 서버로부터 Zone을 복제받을 때 사용됩니다.

## 기본값

- **기본값**: `none` (전송 허용 안 함, 보안상 안전)

## 설정 예시

### 전송 차단 (기본값, 권장)
```
none
```
→ 아무도 Zone 데이터를 복제받을 수 없음 (보안)

### 모든 서버 허용
```
any
```
→ 누구나 Zone 데이터 복제 가능 (위험)

### 특정 서버만 허용
```
192.168.1.10
203.0.113.50
```
→ 지정한 IP 주소만 허용 (권장)

### 내부 네트워크만
```
192.168.0.0/16
10.0.0.0/8
```
→ 내부 네트워크 IP만 허용

### 여러 서버 조합
```
192.168.1.10; 192.168.1.11;
```
→ 여러 slave 서버 허용

## 알아야 할 것들

### Zone 전송이란?

master DNS 서버가 slave 서버에 Zone 데이터를 복제하는 과정:
- **AXFR**: 전체 Zone 전송
- **IXFR**: 증분 Zone 전송 (변경된 부분만)

### 보안 고려사항

**중요**: Zone 전송을 허용하면:
- 도메인의 모든 DNS 레코드 노출
- 네트워크 구조 파악 가능
- 공격자가 정보 수집 가능

**권장 설정**:
- `none`: slave 서버가 없는 경우
- 특정 IP만: slave 서버가 있는 경우

### master-slave 구성

여러 DNS 서버를 운영할 때:
1. master 서버: `AllowTransfer`에 slave IP 지정
2. slave 서버: master 서버로부터 자동 복제
3. 고가용성: master 다운 시에도 서비스 계속

## 자주 발생하는 오류

### Slave 서버가 Zone을 복제받지 못함
**원인**: 
- `AllowTransfer`에 slave IP가 없음
- `none`으로 설정됨

**해결 방법**:
1. slave 서버 IP를 `AllowTransfer`에 추가
2. BIND 재시작
3. 네트워크 연결 확인

### 보안 스캔에서 경고
**원인**: `any`로 설정되어 누구나 Zone 데이터 접근 가능

**해결 방법**:
1. `none`으로 변경 (slave 서버 없는 경우)
2. 또는 특정 IP만 허용 (slave 서버 있는 경우)

### Zone 전송이 느림
**원인**: 네트워크 문제 또는 큰 Zone 파일

**해결 방법**:
1. 네트워크 연결 확인
2. Zone 파일 크기 확인
3. IXFR 사용 (증분 전송)
