# ENSM 배포 가이드

## 배포 구조

ENSM 시스템은 다음 두 가지 구성 요소로 배포됩니다:

1. **JAR 파일**: Spring Boot 애플리케이션 (Java 코드 + 리소스)
2. **스크립트 폴더**: 쉘 스크립트들 (`ensm-scripts/`)

## 배포 전략

### 1. 스크립트 배포

스크립트는 JAR 파일과 별도로 서버에 배포되어야 합니다.

```bash
# 로컬에서 실행
cd Capstone
./ensm-scripts/deploy.sh
```

또는 수동으로:

```bash
# 스크립트 폴더를 서버에 전송
scp -r -P 999 ensm-scripts/ sa@minn0701.iptime.org:/usr/local/bin/ensm-scripts

# 서버에서 실행 권한 부여
ssh -p 999 sa@minn0701.iptime.org
sudo chmod +x /usr/local/bin/ensm-scripts/*/*.sh
```

### 2. JAR 파일 배포

```bash
# 로컬에서 실행
cd ensm-main
./ensm-main.sh deploy
```

또는 수동으로:

```bash
# JAR 파일을 서버에 전송
scp -P 999 build/libs/ensm-main-0.0.1-SNAPSHOT.jar sa@minn0701.iptime.org:/home/sa/
```

### 3. 서버에서 실행

```bash
# 서버에 접속
ssh -p 999 sa@minn0701.iptime.org

# JAR 파일 실행
nohup java -jar ensm-main-0.0.1-SNAPSHOT.jar > app.log 2>&1 &
```

## 서버 디렉토리 구조

서버에 배포된 후 예상되는 구조:

```

├── apache/
│   └── configure_apache.sh
├── bind/
│   └── configure_bind.sh

│   ├── ensm-config.yml
│   └── users.yml
└── ...
```

## 설정 관리

### 기본 스크립트 경로

- **기본 경로**: `/usr/local/bin/ensm-scripts`
- **Apache 스크립트**: `/usr/local/bin/ensm-scripts/apache/configure_apache.sh`
- **BIND 스크립트**: `/usr/local/bin/ensm-scripts/bind/configure_bind.sh`

### 경로 변경

웹 UI에서 설정을 변경할 수 있습니다:
- `/main/ensm/settings` → "스크립트 경로 설정" 섹션

또는 `config/ensm-config.yml` 파일을 직접 수정:

```yaml
ensmScriptsBasePath: "/usr/local/bin/ensm-scripts"
apacheScriptPath: "/usr/local/bin/ensm-scripts/apache/configure_apache.sh"
bindScriptPath: "/usr/local/bin/ensm-scripts/bind/configure_bind.sh"
```

## 주의사항

1. **스크립트 실행 권한**: 모든 `.sh` 파일에 실행 권한이 있어야 합니다 (`chmod +x`)
2. **스크립트 경로**: JAR 파일 실행 시 스크립트 경로가 올바른지 확인하세요
3. **권한**: 스크립트는 `ensm` 사용자 또는 `root` 권한으로 실행될 수 있어야 합니다
4. **경로 변경**: 스크립트 경로를 변경한 후에는 애플리케이션을 재시작해야 합니다

## 문제 해결

### 스크립트를 찾을 수 없음

```
[오류] 명령 실행 실패: No such file or directory
```

**해결 방법**:
1. 스크립트가 서버에 배포되었는지 확인
2. 스크립트 경로가 올바른지 확인 (`/main/ensm/settings`에서 확인)
3. 스크립트에 실행 권한이 있는지 확인: `chmod +x /usr/local/bin/ensm-scripts/*/*.sh`

### 권한 오류

```
[오류] 명령 실행 실패: Permission denied
```

**해결 방법**:
1. 스크립트에 실행 권한 부여: `chmod +x <script_path>`
2. 스크립트가 `ensm` 사용자로 실행 가능한지 확인
3. 필요시 `sudo` 권한 설정
